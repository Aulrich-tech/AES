03 — Activity

One key. One block. Every step.

This is a single item — no separate practice per module. You're given one 16-byte key and one 16-byte plaintext block. Run the key through Key Expansion to get Round 1's key, then run the plaintext through Round 0 and Round 1 of the Encryption Process using the round key you just derived. Same four-step and four-operation loops from both modules — just chained into one worked problem.

Split into words: w0 = 00 01 02 03, w1 = 04 05 06 07, w2 = 08 09 0a 0b, w3 = 0c 0d 0e 0f.

Part 1 — get Round 1's key

Same routine as Key Expansion module 01: only w4 gets the full treatment, w5–w7 are plain XORs.

1. RotWord(w3)
2. SubWord(result) — look each byte up in the S-Box
3. w4 = SubWord result ⊕ w0 ⊕ RCON[1]  (RCON[1] = 01 00 00 00)
4. w5 = w4 ⊕ w1  ·  w6 = w5 ⊕ w2  ·  w7 = w6 ⊕ w3

Part 2 — run the block through Round 0 and Round 1

Same four operations as Encryption Process module 02. Round 0 is just the initial whitening against the raw key; Round 1 is the full SubBytes → ShiftRows → MixColumns → AddRoundKey sequence, closed out with the Round 1 key from Part 1.

1. Round 0: state = plaintext ⊕ key
2. Round 1 — SubBytes: look up every byte in the S-Box
3. Round 1 — ShiftRows: row 0 stays, row 1 shifts by 1, row 2 by 2, row 3 by 3
4. Round 1 — MixColumns: multiply each column against the fixed GF(2⁸) matrix
5. Round 1 — AddRoundKey: XOR against w4 w5 w6 w7 (the key you derived in Part 1)
Why this matters: in modules 01 and 02 the two worked examples used different keys, so there was nothing tying them together. Here there's only one key and one block — the round key you compute in Part 1 is the exact round key AddRoundKey needs in Part 2. Get Part 1 wrong and Part 2 won't match the reveal either.
